Expectations

BayesBase defines a protocol for one question that inference algorithms ask over and over: what is the expectation $\mathbb{E}_q[f]$ of a function f under a distribution q? Backends answer it, and they are defined in other packages: exact closed forms, quadrature, cubature, sampling. Algorithms only ever call the protocol, so a new backend improves every algorithm that uses it.

None of these names is exported. They are public and used qualified, as BayesBase.expectation, so they never clash with names exported by other packages.

using BayesBase, Distributions

backend = SomeBackend()                               # from a backend package
BayesBase.expectation(backend, x -> x^2, Normal(0.0, 1.0))

prepared = BayesBase.prepare_expectation(backend, Normal(0.0, 1.0))
BayesBase.expectation(prepared, x -> x^2)             # many integrands, nodes computed once

Computing expectations

A backend implements one of two things for the distributions it supports.

  • A closed form: a method of BayesBase.expectation for specific types of f and q, such as expectation(::MyBackend, ::typeof(log), q::Gamma).
  • A preparation: a method of BayesBase.prepare_expectation for specific types of q. It returns an object with its own expectation(prepared, f), which works for any integrand, including integrands whose values are dual numbers. Numerical backends return a BayesBase.ExpectationPointSet, a weighted sum over points.

Backends define methods for specific families of distributions only, never for all q. Products of distributions and the routers below rely on that.

BayesBase.expectation — Function
expectation(backend, f, q)

The expectation E_q[f] of the integrand f under the distribution q, computed by backend.

A backend implements either a closed form, a method of expectation for specific types of f and q, or a preparation, a method of prepare_expectation for specific types of q that returns an object with its own expectation(prepared, f). The fallback goes through the preparation.

expectation(prepared, f)

The expectation of f from an object returned by prepare_expectation.

BayesBase.prepare_expectation — Function
prepare_expectation(backend, q)

Prepare the expectations of many integrands under q: nodes, weights and other work that does not depend on the integrand are done once. The result is used as expectation(prepared, f), for any f, including integrands whose values are dual numbers.

The default returns a PreparedExpectation, which forwards every call to the backend.

BayesBase.PreparedExpectation — Type
PreparedExpectation(backend, q)

The default result of prepare_expectation: no work is done in advance, and expectation(prepared, f) calls expectation(backend, f, q).

What a backend supports

BayesBase.supports_expectation answers on types, so that the answer is known to the compiler. Backend owners add methods for the type-level form. The integrand type Any means "every integrand", which is what a numerical method declares:

BayesBase.supports_expectation(::MyQuadrature, ::Type, ::Type{<:Normal}) = true        # any f
BayesBase.supports_expectation(::MyClosedForms, ::Type{typeof(log)}, ::Type{<:Gamma}) = true
BayesBase.supports_expectation — Function
supports_expectation(backend, F::Type, Q::Type)
supports_expectation(backend, f, q)

Whether backend computes expectations of integrands of type F under distributions of type Q. Backend owners add methods for the type-level form; it is false by default. F = Any asks whether every integrand is supported, which is what a numerical method declares with supports_expectation(::MyBackend, ::Type, ::Type{<:MyFamily}) = true.

Labels

A label is a property of a computation that a caller can rely on. A backend declares a label for every pair it supports, or for some pairs only. Labels are conservative: a label is declared only where it is guaranteed.

BayesBase.has_expectation_label(::MyClosedForms, ::BayesBase.ExpectationExact) = true
BayesBase.has_expectation_label(::MyQuadrature, ::Type, ::Type{<:Categorical}, ::BayesBase.ExpectationExact) = true

ExpectationLabel

A property of the computation of an expectation that a caller can rely on. Labels are conservative: a backend declares a label only where it is guaranteed.

Random number generators

A stochastic backend holds its random number generator. The caller never passes one to expectation. Instead, whoever configures the computation, such as an inference engine, fills it in from above with BayesBase.with_expectation_rng, and an RNG set by the user is never overwritten.

BayesBase.with_expectation_rng — Function
with_expectation_rng(backend, rng)

backend with rng filled in wherever it has no random number generator yet. A backend that already has one keeps it, so an RNG set by the user is never overwritten from above. Composite backends fill their parts. The default returns backend unchanged.

source

get_expectation_rng(backend)

The random number generator of backend, or nothing.

Products of distributions

The expectation over several independent variables of different kinds, such as a categorical, a multivariate Gaussian and a point mass, is an expectation under a FactorizedJoint. The integrand receives a tuple with one value per component. A backend supports a product when it supports every component for any integrand. The product is computed as a product rule over the point sets of the components, and labels are combined with BayesBase.combine_expectation_label: exact only if every part is exact, stochastic if any part is stochastic.

BayesBase.ExpectationPointSet — Type
ExpectationPointSet(points, weights)

A prepared expectation that is a weighted sum, Σᵢ wᵢ f(xᵢ): quadrature, cubature, sigma points, exact sums over a finite support, or samples with equal weights. points and weights are anything indexable from one, tuples included. Point sets are the parts of which product rules over a FactorizedJoint are made.

The sum starts from its first term, so its type follows the integrand: dual numbers pass through without the point set knowing about them.

source
BayesBase.ExpectationProductPointSet — Type
ExpectationProductPointSet(sets)

The product rule over a tuple of ExpectationPointSets: every combination of points, weighted by the product of their weights. The integrand receives a tuple of points.

source

Routers

A router is itself a backend that passes each expectation on to one of several backends. BayesBase.ExpectationFirstOf decides on types alone, so the compiler makes the choice and nothing is decided at run time. BayesBase.ExpectationDynamicRouter chooses at run time among the backends that packages have registered, and is meant for interactive use. ExpectationFirstOf(ExpectationDynamicRouter()) freezes its current choice into an ExpectationFirstOf.

BayesBase.ExpectationFirstOf — Type
ExpectationFirstOf(backends...; prefer = (), exclude = ())

A router, itself a backend: each expectation goes to the first of backends that supports the pair (f, q) and has none of the labels in exclude. With prefer, the first backend that also has all the labels in prefer wins, when there is one. The choice depends on types only, so inference makes it and nothing is decided at run time.

A product of distributions (FactorizedJoint) is routed component by component.

source
BayesBase.ExpectationDynamicRouter — Type
ExpectationDynamicRouter(registry = the global registry)

A router that chooses among registered backends at run time. Ranking: exact for the pair first, then not stochastic, then higher priority, then the name of the backend's type. Never the order of registration, so the result does not depend on which package was loaded first.

Type-unstable by design, and opt-in: never a default and never used inside library code. ExpectationFirstOf(ExpectationDynamicRouter()) freezes the current choice into a type-stable router.

source

ExpectationBackendRegistry()

BayesBase.expectation_backend_priority — Function
expectation_backend_priority(backend; registry = the global registry) -> Union{Int, Nothing}

The priority backend was registered with, nothing when it is not registered. A negative priority marks a last resort, a backend chosen only where no other applies; a report of an inference may say where one was. A frozen ExpectationFirstOf keeps the order the priorities gave, not the priorities, so this asks the registry.
